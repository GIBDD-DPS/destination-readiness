# Destination Readiness

> **Prizolov Lab** · Автор: Dm.Andreyanov · Версия: v0.1.0-draft

Независимая методология и сервис оценки готовности туристического направления к поездке — по датам, а не по городу вообще. Не связан с проектом Agenomics — отдельный продукт с собственной архитектурой.

## Идея

Существующие рейтинги направлений (отзывы, рейтинги отелей) не показывают структурных проблем: перегруженность инфраструктуры в конкретный месяц, риск новых ограничений, реальное время в очереди, напряжённость между жителями и туристами, ценовые аномалии. **Destination Readiness** — 13 независимых осей + персональный блок Trip Cost & Feasibility, каждая со своей формулой, источником данных и обязательной причиной (`reason`) для присвоенного значения.

## Ключевые архитектурные принципы

1. **Каждая ось — независимый модуль.** Сбой или отсутствие данных в одной оси (`not_applicable`) не должен ронять остальные — см. `build_report()` в `backend/app/main.py`, использующий `asyncio.gather(..., return_exceptions=True)`.
2. **Обязательная причина, не только число.** Каждый результат несёт `description` (что измеряется) и `reason` (почему именно такое значение) — реализовано и в прототипе дашборда, и в схеме БД (`axis_reasons_i18n`).
3. **Постепенная автоматизация без потери доверия.** Численные оси (погода, валюта, инфраструктура) автоматизируются сразу. Текстовые/интерпретирующие оси (регуляторный риск, локальные настроения, риск забастовок) проходят через `LEARNING → CALIBRATING → TRUSTED → AUTONOMOUS` с постоянным контрольным аудитом 1% даже на максимальном уровне доверия — см. `docs/automation_trust_tiers.md`.
4. **Двуязычность на уровне данных, не перевода на лету.** RU/EN тексты причин хранятся как отдельные записи, язык интерфейса определяется по вводу пользователя (кириллица/латиница) с ручным оверрайдом.
